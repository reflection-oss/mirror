# Contributing to Mirror

Mirror is maintained by Reflection AI. We welcome bug reports and feature
requests through GitHub issues.

For now, we are not accepting external code or documentation contributions.
We will consider opening up contributions in the future.

If you would like to contribute, please express your interest using `/feedback`
in the Mirror CLI or [this GitHub form](https://github.com/reflection-oss/mirror/issues/new/choose).
`/feedback` opens the GitHub issue form.

## Reporting issues

For suspected security vulnerabilities, follow [SECURITY.md](SECURITY.md)
instead of using `/feedback` or public GitHub issues.

Search [existing issues](https://github.com/reflection-oss/mirror/issues)
before [opening a new issue](https://github.com/reflection-oss/mirror/issues/new/choose).

Keep each issue focused on one bug or request. If an existing issue covers the
problem, add useful new details there rather than opening a duplicate.

For bug reports, include:

- Mirror version (`mirror --version`) and commit if built from source.
- Operating system and terminal app.
- Steps to reproduce the problem.
- What you expected and what happened.
- Relevant error messages or logs.

For feature requests, explain the problem you want to solve and the behavior
you would like.

Review logs, screenshots, and attachments before posting. Remove API keys,
access tokens, private source code, and personal information.

## Report quality and triage

If you use AI to help prepare a report, review it before posting. Verify the
steps, logs, and claims yourself, and distinguish observed behavior from
suggestions or hypotheses. Do not submit unreviewed generated reports or bulk
automated issues.

Maintainers may ask for more information or close duplicate reports and issues
that lack enough detail to investigate. Add requested details to the existing
issue so the discussion stays in one place.

Issue discussions must follow our [Code of Conduct](CODE_OF_CONDUCT.md).
